# 北九州購物清單商品管理

## 目標

使用者最常見的用法是**直接丟一張照片**（在店裡拍的、網頁截圖、社群貼文圖），
說一句「加到清單」。你要自己補完其餘欄位，不要反問一堆問題。
網站的唯一資料來源是 `assets/products.js`；不要建立第二份商品清單。

---

## A. 只給圖片時的流程（最常見，照這條走）

### A0. 先確定圖片在哪、夠不夠大

使用者給圖有三種方式，**優先順序由上而下**（越上面畫質越好）：

**（1）本機資料夾路徑**——最理想，通常是原始照片，解析度最高。

使用者可能只說「圖在桌面那個資料夾」而沒給完整路徑。這時直接找，
不要反問：先看他提到的資料夾，挑修改時間最近、且尺寸合理的圖片檔。
找到多張分不清是哪張時，才列出候選問他。

**（2）直接貼在對話裡**——貼上的圖會存到：

```
~/.claude/image-cache/<session-id>/<流水號>.png
```

`<session-id>` 就是你的 scratchpad 路徑裡那一段 UUID。取用方式：

```bash
ls -t ~/.claude/image-cache/<session-id>/*.png | head -5
```

`-t` 是按時間排序，**最新的就是他剛貼的那張**。多張一起貼時流水號連號。
拿到後先 Read 開來看，確認是你要處理的那張商品圖，不要憑檔名猜。

若這個路徑不存在（不同版本的 Claude Code 可能不同），
就直接請使用者把圖存成檔案再給路徑，不要卡在這裡試。

**（3）官方商品頁的圖**——前兩者都沒有時才用。

### A0-1. 檢查解析度（會影響成品畫質，必做）

不管圖從哪來，加進去之前先量：

```bash
sips -g pixelWidth -g pixelHeight <圖片路徑>
```

判斷標準（`build:images` 產生的縮圖是 400px、大圖是 1200px）：

| 最長邊 | 處理方式 |
|---|---|
| ≥ 1200px | 直接用，最好 |
| 400–1199px | 可以用，但大圖會偏糊；有原始檔的話跟使用者要 |
| < 400px | **不要用**。卡片圖顯示 156 CSS px，手機是 2～3 倍螢幕，這種圖會明顯糊。請使用者重拍或給原始檔 |

**貼在對話裡的圖特別容易踩到這條**——那通常是螢幕截圖而不是原始照片，
截到的商品區域可能只有兩三百 px。量到偏小就明講，不要默默用下去。

另外，截圖常常整個畫面都在裡面（含瀏覽器介面、其他商品）。
**一定要先裁切出商品本身**再進管線，不要把整張截圖當商品圖。

### A1. 先看圖，把能讀到的都讀出來

一張圖有多項商品時，**先裁切成各商品一張**，再逐項處理，不要合成一筆。

從圖上讀：品牌、日文品名、型號、容量／入數（例：180mL、30 枚）、
以及**價格標籤**（有沒有拍到標價會決定 `priceKind`）。

讀得到就記下來；讀不到不要猜，下一步查。

### A2. 查證，不要靠印象

拿 A1 讀到的日文品名去查官方網站，確認正式名稱、規格與價格，
規則見 `references/source-policy.md`。查證順序：
官方網站 → 日本大型通路 → 品牌新聞稿。

**只有這三種情況才問使用者**：圖太模糊連品牌都認不出來、
查到兩個規格相近無法判斷是哪個、照片是別人商品的側拍無法定位。
其餘一律自己查完。**絕對不能拿相似商品代替。**

### A3. 決定 id

英文小寫連字號，格式 `品牌-商品名`（例：`morinaga-caramelic-pudding`）。
**id 一旦寫入就不可更改**——使用者手機的已購買狀態存在 localStorage，
key 就是這個 id，改了等於把他勾好的紀錄清空。

### A4. 圖片：走建置腳本，不要手工轉檔

這是最容易做錯的一步。正確做法只有三個動作：

1. 原圖存成 `images/source/<id>.<副檔名>`（保留原始檔，不要先壓縮）
   —— 對話貼上的圖用 `cp` 從 `image-cache` 複製過來，不要只留在快取裡，
   那個資料夾會隨對話清掉，之後重跑建置就找不到來源
2. 在 `images/build-manifest.json` 加一行：`"<id>": "images/source/<id>.jpg"`
3. 跑 `npm run build:images`

腳本會自動產生 `images/thumb/<id>.webp`（400px）與 `images/full/<id>.webp`（1200px）。

**不要**自己用 sips／sharp 手動產生 thumb 或 full，
**不要**把圖片直接丟進 `images/thumb/`——沒進 manifest 的圖，
下次別人重跑建置就會被漏掉或蓋掉。

商品欄位的 `image` 一律寫 `images/thumb/<id>.webp`。

沒有可用的使用者圖片時，才去找官方商品圖，一樣走上面三步。

### A5. 寫入資料

用 `templates/product-record.js`，**只在 `BASE_PRODUCTS` 最後追加**。
不要重排、改名或刪除既有商品。

### A6. 驗證（三個都要跑，不能只跑一個）

```
npm run validate:data     # 欄位、價格、來源網址格式
npm test                  # 卡片契約、店家顯示名稱齊全
```

然後開瀏覽器實測 **390px 與 1280px**，確認：
新商品看得到、圖片載得出來、價格種類正確、卡片沒有橫向溢出。
有寫 `stores` 的話，點一次店家連結確認會跳到地圖並選中那家店。

### A7. 回報

寫清楚：新增了什麼、價格用哪一種來源、**哪些資訊仍待確認**、驗證結果。
待確認的事項要明講，不要含糊帶過。

## B. 給商品名稱或網址時

跳過 A1，其餘相同。圖片改從官方商品頁取得，一樣走 A0-1 的解析度檢查與 A4 的三步驟。

## 欄位規則

完整範例見 `templates/product-record.js`。以下是容易寫錯的地方。

### group（四選一）

| group | 放什麼 | tracking |
|---|---|---|
| `shopping` | 藥妝、日用品、一般伴手禮 | `buy` |
| `convenience` | Lawson／7-ELEVEN／FamilyMart 的食品飲品 | `buy` |
| `dryer` | 吹風機 | `buy` |
| `shoes` | 鞋款（到店試穿） | `try` |

### name（中文品名）——會直接影響版面

手機卡片右欄只有 **172px**。實測：

- 17 字以內 → 一行
- 18–24 字 → 兩行（可接受）
- 25 字以上 → 三行，卡片明顯變高

**盡量壓在 20 字以內。** 冗長的英文型號往 `model` 欄放，不要塞進 `name`。
反例：`CIO SMARTCOBY SLIMII Wireless 2.2 8K 行動電源`（41 字，佔三行）。

### jaName 與 model

這兩個欄位**會被合併成同一行**，用「・」分隔。所以 `model` 不要重複
`jaName` 已經有的內容，否則會出現「ヘアドライヤー・ヘアドライヤー」。
吹風機的型號本身就是品名，程式會自動略過 `model`。

### defaultQty（遺留欄位，不用花時間想）

數量控制已於 2026-08-13 從介面移除，這個欄位**不再被任何程式讀取**，
只是驗證器還要求它存在。`tracking: 'buy'` 一律填 `1`，`tracking: 'try'` 一律填 `null`。
不要研究「應該買幾個」。

### twdRef

固定 `null`。台幣由 `JPY_TWD_RATE` 自動換算，手寫值會被驗證器擋下。

### 價格四欄要一起給

`yen`、`priceKind`、`priceSourceUrl`、`priceCheckedAt` 是一組，不能只給一部分。

| priceKind | 用在什麼情況 | 注意 |
|---|---|---|
| `official` | 日本官方定價 | |
| `retailer-reference` | 可信日本通路參考價 | 卡片會標「通路參考價」 |
| `launch-reference` | 已停產／舊款的上市價 | |
| `photo-reference` | 使用者原始照片同時拍到商品與標價 | `priceSourceUrl` 必須是 `null`，`priceNote` 註明型號或包裝 |
| `pending` | 查不到可靠價格 | `yen` 必須是 `null`，`priceNote` 必填且要寫清楚為什麼查不到 |

有可靠價格時 `priceNote` 填 `null`。
`priceSourceUrl` 必須是**單品頁**——首頁與站內搜尋頁會被驗證器擋下。

便利商店的商品現在**也會顯示價格**（以前刻意不顯示），所以超商品項一樣要好好查價。

### stores——寫錯會靜靜地不顯示

`stores` 裡的每個 id 必須**同時滿足兩個條件**：

1. 存在於 `map.html` 的 `STORES` 陣列
2. 存在於 `index.html` 的 `STORE_SUMMARIES`

少了第 2 個，店家連結**不會報錯，只是整條消失**，畫面上看不出來。
（實際發生過：7 項商品的店家連結靜靜不見了一段時間。）
`npm test` 現在會擋這個情況——測試紅燈時就是叫你去 `STORE_SUMMARIES` 補一行。

要新增一家店時，`map.html` 的 `STORES` 與 `index.html` 的 `STORE_SUMMARIES` 兩邊都要加。

只有品牌或店家官方資料可以證實時才寫 `stores`。
沒有可靠證據就留空陣列——不能用距離、搜尋結果或推測填。
鞋款不需要 `stores`（店家已寫在品牌分區標題）。

### category

便利商店用既有分類：`冰品`、`麵包甜點`、`飲品`、`即食湯品`。
新增分類要連頁面色票對照一起補齊，否則標籤會沒有顏色。

## 來源紀錄

新增或更新 `docs/product-price-sources-YYYY-MM-DD.md`，
列出商品、價格、價格種類、直接來源網址與查證日期。
圖片來源與使用限制也寫在這裡。

---

## 禁止事項

- 不使用「官方目前無定價，現場請直接詢問門市」當作價格說明。
- 不擅自刪除或改名既有商品 id、圖片、來源紀錄。
- 不以台灣價格、跨境代購價或未驗證的社群貼文當作日本售價。
- 不把無法證實的店家寫進 `stores`。
- 不手工產生 `images/thumb/` 或 `images/full/` 的檔案。
- 不跳過 `npm test`——它擋的正是「畫面上看不出來」的那類錯誤。
