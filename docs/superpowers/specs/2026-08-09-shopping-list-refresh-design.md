# 北九州購物清單改版設計

## 目標

將購物清單改為與地圖頁一致的米白、深綠風格與桌面雙欄大卡版面；補上可追溯的價格資訊；移除收藏與店員模式；建立可由自然語句觸發的商品新增 Skill。

## 已確認需求

- 桌面版每列兩張商品卡片，手機版維持單欄。
- 商品圖、名稱、價格與說明要比現況更大。
- 清單頁套用地圖頁的色彩、卡片與標題風格。
- 完整移除收藏功能，包括底部入口、卡片愛心與儲存鍵。
- 一般商品採文字按鈕「未購買／已購買」；鞋款採「未試穿／已試穿」。
- 完整移除店員模式、圖片放大按鈕與日文求助浮層。
- 底部導覽保留清單、地圖、結算。
- 商品新增採 Skill 自動研究模式：使用者提供名稱或網址後，查找資料、保留既有資料、寫入網站共用商品資料並驗證。

## 資料與價格

`assets/products.js` 繼續作為唯一商品資料源。每一筆商品新增 `priceKind`、`priceSourceUrl`、`priceCheckedAt` 欄位，明確標示官方定價、通路參考價或舊款上市價。價格不確定時不寫入總金額，卡片改顯示「價格待確認」與原因；不得以「現場請直接詢問門市」作為預設文案。

既有缺價商品預計以可追溯來源補齊：Cloudtilt ¥23,100、Bondi 9 ¥24,200、Skyflow ¥22,000、Gaviota 5 上市參考價 ¥27,500、掛勾式浴室海綿通路參考價 ¥551、茅乃舍茶碗蒸調味包單包 ¥237。舊款與通路價會在卡片上標示其性質，避免誤當作現行官方定價。

## 介面

清單內容區最大寬度為 1180 px。桌面寬度達 760 px 時使用兩欄網格；較小寬度使用單欄。每張卡片有較大的商品圖片、分類標籤、商品名稱、日文名／型號、價格與短說明；操作區使用可讀的狀態按鈕，不使用只有圖示的方框。

地圖頁不改變其商店互動。新商品若有官方可證實的門市關聯才填入 `stores`，使既有地圖能自動呈現商品縮圖；否則維持空陣列，不推測店鋪。

## 商品新增 Skill

Skill 放在專案的 `skills/kij-shopping-list/`，並提供可安裝到個人 Codex Skills 目錄的說明。觸發情境為「新增購物清單商品」、「把這個商品加到北九州清單」與提供商品網址。它必須：

1. 確認商品規格、包裝／型號與日本價格來源。
2. 優先使用官方來源，次選可信日本通路；記錄價格性質與查證日期。
3. 下載或整理符合授權與引用需求的商品圖片，建立縮圖與全圖。
4. 以穩定、不重複的 id 新增資料，不重新排序或修改舊商品。
5. 執行資料驗證與本機瀏覽器驗收；如有門市資訊才更新地圖關聯。
6. 產生一份來源記錄，讓後續能重新查證。

## 驗收

- `npm run validate:data` 成功，包含新增欄位及資料完整性檢查。
- 桌面 1280 px 為雙欄，手機 390 px 為單欄，沒有水平溢出。
- 已購買／已試穿按鈕可切換並刷新後保留。
- 頁面不再出現收藏或店員模式相關控制、文案或 localStorage 寫入。
- 地圖可載入，清單與地圖的商品連結正常。
- 部署前由 sol 進行獨立審查；審查、測試與瀏覽器驗收均通過後才部署。
