# KIJ 購物清單 UX/UI 改版設計規格

日期：2026-08-05（台北時間，2026-08-06 補追加項目）
狀態：使用者已核准，進入實作
範圍：`index.html`（購物清單）、`map.html`（博多天神地圖，2026-08-06 起擴及小倉商圈）

---

## 一、為什麼要改

現有兩頁功能可用、資料有出處，但使用者提出的核心問題是「外觀不夠好看」，而在釐清過程中浮現一個更實際的需求：**在日本店裡要把商品照片拿給店員看**，現有卡片的縮圖不足以支撐這個用法。

使用情境已確認為 **手機現場優先、電腦大螢幕為輔**。設計因此以單手操作、戶外強光可讀、少步驟為原則。

同時兩頁樣式各自獨立，改一邊另一邊不會跟著變，分類配色甚至已經出現不一致（地圖的藥妝／超市顏色與原始規劃相反）。本次一併收斂。

## 二、已定案的設計決定

| 項目 | 決定 |
|---|---|
| 視覺風格 | **明亮活潑**：暖白底 `#fffdf8`、珊瑚橘主色 `#ff6b45`、大圓角、分類色票 |
| 整頁佈局 | 頂部固定區（頁首＋進度合計＋分類頁籤）＋ 可收合分區 ＋ 底部固定工具列 |
| 分類頁籤行為 | 「跳轉＋聚焦」而非另一套篩選：點某分類即捲至該區並展開、其餘收合；「全部」＝全展開 |

| 地圖範圍 | 統一外觀 ＋ **「這家店可買哪幾項」連動**（不含定位功能） |
| 資料架構 | 抽出 `assets/products.js` 作為兩頁共用的單一資料來源 |

## 三、現況盤點（本次設計的事實基礎）

以 grep 實測 `index.html`：

- `<article>` 卡片共 **32** 張：藥妝日用（`data-group="shopping"`）18 張皆有 `data-price`／`data-unit-price`／`data-default-qty`、有「已購買」勾選＋數量；吹風機（`"dryer"`）2 張同樣有價格與購買欄位；吹風機評價卡（`class="review-card"`）2 張，非商品、僅陳列評分；鞋款（`class="card shoe"`）10 張。
- **鞋款卡片沒有價格／數量欄位**，只有「已試穿」勾選（`class="shoebox"`，10 張皆同）。這是既有的刻意設計差異，不是缺陷：鞋子要現場試才知道尺寸，不像藥妝可以直接下單。改版須保留此區別，不可強行套上「已購買＋數量」的介面。
- 藥妝日用底下有 6 個子分類（`data-category`）：日用品 6、皮膚護理 4、食品伴手禮 4、旅途常備藥 2、痠痛舒緩 1、3C 配件 1，合計 18。
- 篩選按鈕 9 顆（全部 ＋ 6 子分類 ＋ 吹風機 ＋ ON & HOKA）。
- 圖片：外部檔案 **7** 張、base64 內嵌 **23** 張。內嵌的 23 張中，**10 張其實是程式產生的 SVG 佔位圖**（灰底＋品名文字），並非真實商品照——即全部 10 張鞋款卡片皆用佔位圖，沒有一張是真照片。
- **`images/on/`（10 張）與 `images/hoka/`（5 張）資料夾內已有 15 張真實鞋款照片，完全沒有被任何頁面引用。** ON 系列 5 款各有 side／top 兩角度，HOKA 系列 5 款各 1 張，與 10 個鞋款 id 逐一對得上。這批照片已經拍好／下載好卻沒用上，是本次「給店員看」功能最直接可以填的缺口，優先權高於外部化既有的 13 張真實 base64 照片。
- localStorage：明確具名的僅 `v40_rate`（匯率快取，`index.html:944`）；其餘為 `keyFor(el, i)` 依 DOM 索引產生的鍵，以及 `KEY+'fav_'+id`（收藏，`index.html:1042`）。

### ⚠️ 資料缺口：日文品名與型號

全檔含片假名的行僅 **13** 行，代表**大多數商品沒有日文正式品名**，型號欄位亦多數缺漏。

「給店員看」的價值完全建立在日文品名與型號上，缺了就只剩一張照片。因此**補齊這兩個欄位是本次的必要工作項，不是選配**。作法：以現有 `docs/` 研究檔與商品官方頁面逐項查證填入；查不到的商品在資料中標記 `jaName: null`，店員模式對這類商品只顯示照片與中文名，不顯示空欄位，也不得自行編造日文名稱。

### localStorage 依 DOM 索引產生鍵的風險

`keyFor(el, i)` 用元素在 `.persist,.shoebox` 集合中的**索引**當鍵。本次改版會重排 DOM，舊鍵將全數對不上，使用者既有的勾選與數量會遺失。

處理方式：改為以商品 `id` ＋ 欄位名產生鍵（例如 `kij_bought_ebisu-premium-care`），並在首次載入時執行一次性搬遷，讀不到舊值就沿用預設值。改版後鍵值與 DOM 順序脫鉤，日後再調整版面不會再遺失資料。

## 五、資料層：`assets/products.js`

單一資料來源，兩頁共讀。匯出一個陣列，每項結構如下：

```js
{
  id: 'ebisu-premium-care',      // 唯一鍵，同時作為 localStorage 鍵與地圖連動的參照
  group: 'shopping',             // shopping | dryer | shoes
  tracking: 'buy',               // 'buy'：已購買＋數量（shopping／dryer）；'try'：已試穿、無數量（shoes）
  category: '日用品',             // 藥妝日用底下的子分類；dryer/shoes 可為 null
  name: 'EBISU 優質牙刷',         // 中文品名
  jaName: 'エビス プレミアムケア', // 日文正式品名；查不到填 null
  model: null,                   // 型號，如 'EH-NE7N'；無則 null
  yen: 398,                      // 日圓參考價；鞋款若無可追溯官方現價則填 null（見第八節第 4 點）
  twdRef: null,                  // 台灣同款售價，用於比價；無則 null
  defaultQty: 3,                 // tracking:'try' 的商品固定為 null，UI 不顯示數量欄
  image: 'images/products/ebisu-premium-care.webp',
  note: '推薦理由一句',
  source: 'docs/japan-product-prices-2026-08-01.md',  // 價格出處，可追溯
  stores: ['donki-nakasu', 'daiso-hakata']            // 在哪幾家店買得到，對應 map.html 的店家 id
}
```

`tracking:'try'` 的商品（10 款鞋）在清單頁顯示「已試穿」勾選、不顯示數量與已購買欄位，維持與現況一致的語意：鞋子要現場試穿才知道尺寸，不是下單項目。

`index.html` 由此陣列渲染清單，`map.html` 由此陣列反查每家店可買（或可試穿）的品項。價格與品項日後只需改這一個檔案，兩頁同步更新。

`stores` 欄位是「這家店可買哪幾項」的資料基礎；`map.html` 現有 9 家店需先確定各自的 id，再逐項標註對應關係。無法確定是否有貨的組合就不填，寧缺勿錯。

### 圖片：兩件分開的工作

**1）串接已存在但未使用的鞋款照片（優先，且是本次唯一「新增內容」而非單純外觀調整）**
`images/on/`（10 張，ON 五款各 side／top 兩角度）與 `images/hoka/`（5 張，各 1 張）已經在 repo 裡，但 10 張鞋款卡片目前全用 SVG 佔位圖。改版把這 15 張接上對應商品：ON 系列預設用 `-side` 角度做縮圖與店員模式主圖，`-top` 角度暫不使用（YAGNI，多角度切換非本次範圍）。串接後鞋款卡片才有真照片可以拿給店員看。

**2）13 張真實 base64 照片外部化**
藥妝日用與吹風機共 13 張目前內嵌在 HTML 裡的真實照片（23 張 base64 中扣除 10 張鞋款佔位圖），改存為 `images/` 下的實體檔案，並提供兩種尺寸：

- 縮圖 `images/thumb/<id>.webp`（長邊 200px）供清單使用
- 原圖 `images/full/<id>.webp`（長邊 1200px）供店員模式使用

主因是店員模式需要大圖、清單需要小縮圖，內嵌格式無法支援兩種用途；附帶效益是 `index.html` 由 3.7 MB 降至約 200 KB。

兩項工作合計後，全部 20 個購買型商品 ＋ 10 個鞋款，共 30 項在改版後都有真實照片可用（原本 7 張外部檔案維持不動，一併統一放進 `images/thumb/`／`images/full/` 兩種尺寸）。

## 六、購物清單頁 `index.html`

由上而下：

1. **頁首**：標題 ＋ 即時台銀匯率。
2. **進度合計條**：「已買 N / 23 項」（23 為 `tracking:'buy'` 商品總數，不含鞋款；含第十二節新增的 3 項）與台幣合計。
3. **分類頁籤**：全部 ／ 6 個藥妝子分類 ／ 吹風機 ／ ON & HOKA，橫向可捲。

以上三塊 `position:sticky` 釘在頂端，捲動不消失。

4. **可收合分區**：依 `group` 分三區，區標題顯示「已買 9 / 14」（鞋款區顯示「已試穿 2 / 10」）與展開狀態箭頭。收合狀態以 `id` 存入 localStorage。
5. **商品卡**：左側 66px 縮圖（右下角 ⤢ 提示可放大）／中間中文名、日文名、分類徽章／右側 26px 勾選框。`tracking:'buy'` 卡片另顯示價格塊與數量加減；`tracking:'try'`（鞋款）卡片顯示「已試穿」勾選，不顯示價格與數量欄——沒有可靠官方售價的商品不硬湊數字。
6. **底部工具列**：清單／地圖／結算／收藏，固定於底部，兩頁共用同一元件。「結算」加總僅計入 `tracking:'buy'` 且 `yen` 非 null 的品項。

### 店員模式（全螢幕覆蓋層）

點卡片縮圖開啟。由上而下：關閉列 → 大圖（`images/full/`，鞋款用 `images/on/`／`images/hoka/` 的 `-side` 角度）→ 深色資訊區：日文正式品名（19px 粗體）、型號（等寬字）、日文求助句、需求說明。`tracking:'buy'` 顯示「要買數量與參考價」；`tracking:'try'`（鞋款）改顯示「想試穿的尺寸」（沿用現有現場填寫欄位），不顯示參考價（`yen` 為 null 時不顯示空白）。

日文求助句固定為：

```
この商品を探しています。
置き場所を教えていただけますか？
```

`jaName` 為 null 的商品不顯示日文名區塊，改以中文名與照片為主。

## 七、地圖頁 `map.html`

- 套用 `assets/kij.css`，與清單頁同一套配色、圓角、陰影。
- 加入同一個底部工具列，「地圖」為作用中狀態，一鍵回清單。
- 修正藥妝／超市顏色對調（現況 `map.html:38,40` 與原始規劃相反）。
- 篩選按鈕與卡片內連結觸控高度提升至 44px。
- **每張店家卡片新增「這裡可買 N 項」**：反查 `products.js` 中 `stores` 含此店 id 的商品，顯示品項縮圖列（最多 5 張，超出顯示「+N」）。點任一縮圖跳回 `index.html` 並定位到該商品（以 `#id` 錨點，載入後展開所屬分區並短暫高亮）。
- 補上原規劃未做的空狀態「重設篩選」按鈕（現況 `map.html:531` 僅有文字）。
- 圖磚載入失敗的既有降級機制（`map.html:892-907`）維持不動，該設計正確。

## 八、順帶修正的既有缺陷

改版會重寫這些區域，順手修掉上次檢視發現的問題：

1. **鞋款卡片全用 SVG 佔位圖，`images/on/`、`images/hoka/` 裡 15 張真實照片完全未串接**（見第三節）。這是本次影響最大的一項——「給店員看」對鞋款目前完全不成立。
2. 「已購買」勾選重整即消失（`index.html:279` 起 20 個核取方塊缺 `persist` class）。改為以商品 id 為鍵保存。
3. 跨分類搜尋無結果時空白畫面不顯示提示（`index.html:1046-1048` 的 `catOK` 判斷失準）。
4. EH-NE7N 畫面寫死 ¥10,470 與計價用的 ¥6,630 不符（`index.html:500,504`）。以 `products.js` 單一數值為準。
5. 三張鞋卡列出無可追溯來源的「官網定價」（`index.html:833` 等），與 `docs/japan-product-prices-2026-08-01.md:40-43` 的明確聲明矛盾。`products.js` 中對應 `yen` 填 null，畫面不顯示該欄位，不得沿用舊數字。
6. HaRENO 牙刷推薦理由寫「螺旋刷毛」、款式欄寫「一般刷毛」（`index.html:471`）。以查證結果擇一。

## 九、錯誤與邊界狀態

| 情況 | 行為 |
|---|---|
| 匯率抓取失敗 | 顯示上次成功的匯率與時間戳，標註「離線值」，不留空白 |
| 商品圖片載入失敗 | 顯示分類色底的佔位方塊與品名首字，不顯示破圖 |
| `jaName` 為 null | 店員模式隱藏日文區塊，不顯示空欄位 |
| `yen` 為 null（無可追溯官方價） | 卡片與店員模式皆不顯示價格欄，不沿用舊資料或估算值 |
| 某店無對應商品 | 店家卡片不顯示「可買 N 項」區塊，而非顯示「可買 0 項」 |
| 地圖圖磚失敗 | 維持現有降級：隱藏地圖、保留店家清單與 Google Maps 連結 |
| localStorage 不可用 | 功能照常運作，僅不保存狀態，不拋錯中斷頁面 |

## 十一、驗收方式

改版完成須通過以下檢查，且證據為實際輸出而非目視：

1. **渲染**：headless Chrome 於 390px 寬（iPhone 15 尺寸）與 1280px 寬各開 `index.html`、`map.html` 截圖，四張畫面皆正常，無破圖、無水平捲軸。
2. **狀態保存**：勾選 3 項、改 1 項數量、收合 1 個分區 → 重新整理 → 三者皆保留。
3. **店員模式**：點任一有 `jaName` 的商品縮圖，全螢幕顯示大圖與日文名；點 `jaName` 為 null 的商品，不出現空白日文區塊。點任一鞋款卡片，顯示 `images/on/`或`images/hoka/` 的真實照片，不再出現 SVG 佔位圖。
4. **地圖連動**：任一家店的「可買 N 項」數字與 `products.js` 中 `stores` 欄位實際筆數相符；點縮圖跳回清單並定位到正確商品。
5. **資料一致性**：`products.js` 中每項 `yen` 非 null 者，數值與 `source` 指向的 `docs/` 檔案一致，且 `source` 不得為空；`yen` 為 null 者 `source` 允許為空。
6. **中文品質**：全檔無簡體字；中英數字間半形空格一致。
7. **體積**：`index.html` 小於 300 KB。

驗收由未參與實作的 fresh-context agent 執行，實跑並貼出輸出。
